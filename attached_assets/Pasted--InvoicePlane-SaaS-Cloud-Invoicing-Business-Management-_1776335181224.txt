## ✨ Features

### 1. Authentication System
- JWT-based authentication with httpOnly cookies
- User registration (invite-code-gated when users exist) and login
- Access token (60 min) + Refresh token (7 days)
- Protected routes with auto token refresh
- Rate-limited login endpoint

### 2. User Management (Admin)
- Admin-only CRUD for user accounts
- Role assignment (`user` / `admin`)
- One-time admin bootstrap via `/api/setup`

### 3. Client Management
- Full CRUD operations with pagination and sorting
- Auto-generated client codes (e.g., "AC001")
- Search and filter (active/inactive)
- ISO certifications tracking
- CSV import/export
- Bulk delete and bulk mark-inactive

### 4. Consultant Management
- CRUD with auto-seeded defaults (TY, PL, PW)
- Short code assignment
- Assignment to invoices for revenue tracking

### 5. Invoice System
- **Status workflow** (session API): Draft → Pending approval → Approved → Sent → Revised → Paid (there is no separate “viewed” step in the status model)
- Line items with quantity, price, tax rate
- Discount support (percentage or fixed)
- Multi-currency (HKD, USD, CNY, MOP)
- Consultant assignment (up to 3)
- PDF generation with company branding
- Auto-generated invoice numbers (YYMM-NNN)
- Email invoice PDF to client (SMTP or Gmail API)
- Send payment reminder emails
- Bulk delete and bulk status updates
- CSV import/export

### 6. Quotation System
- **Status workflow** (session API): Draft → Pending approval → Sent → Approved → Confirmed or Canceled (no “viewed” step)
- Convert to Invoice, convert to Job Order only, or **Confirm-and-Convert** (creates both Invoice and Job Order in one step)
- Convert to Job Order
- Lookup by quotation number
- Line items management with remarks and terms
- PDF generation and email delivery
- Reusable quotation templates
- Auto-generated quotation numbers (QYYMM-NNN)

### 7. Job Orders
- Manual creation and edit
- Convert from Quotation or from Invoice
- **AI PDF Extraction** using DeepSeek API
- Extract company info and line items from uploaded PDFs
- PDF generation and email delivery
- Auto-generated job order numbers (JOYYMM-NNN)

### 8. Payment Tracking
- Record payments against invoices
- Multiple payment methods (bank transfer, cash, check, credit card, other)
- Auto-update invoice paid status
- Payment reversal (delete) with automatic status rollback
- Receipt file upload per payment

### 9. Recurring Invoices
- Schedule invoices to recur on a defined frequency
- Enable/disable individual schedules
- Batch-process all due recurring invoices via single endpoint

### 10. Revenue Dashboard
- Summary stats card (revenue, invoices, quotations, payments)
- Monthly revenue bar chart
- Revenue by consultant breakdown
- Year selector

### 11. Company Settings
- Company information and two bank accounts configuration
- Logo upload (company logo + header logo), optional per-logo scale (`company_logo_scale`, `header_logo_scale`), and signature image upload (`signature_image`)
- AI API configuration (DeepSeek/OpenAI-compatible)
- Default currency setting
- Gmail service account upload/removal
- SMTP or Gmail API email accounts

### 12. Public REST API (v1)
- API key management (admin generate/revoke)
- `X-API-Key` authenticated endpoints for clients, invoices, quotations, job orders, and payments

## 🗄 Database Schema

### Collections Overview

```
MongoDB Database: invoiceplane
├── users                  # User accounts
├── clients                # Client/customer records
├── consultants            # Team members
├── invoices               # Invoice documents
├── quotations             # Quotation documents
├── quotation_templates    # Reusable quotation templates
├── job_orders             # Job order documents
├── payments               # Payment records
├── recurring_invoices     # Recurring invoice schedules
├── uploaded_files         # Base64 copies of uploads (logos, receipts) for restore after restart
└── company_settings       # Company configuration (includes public API key material for v1)
```

## 🔄 Business Logic & Workflows

### Invoice status workflow (session API)

Typical progression enforced by `PATCH /invoices/{id}/status`:

```
DRAFT → PENDING_APPROVAL → APPROVED → SENT → REVISED → PAID
```

There is no `viewed` status in this pipeline. Some older UI or data may still show legacy values such as `viewed` or `email_sent`; treat those as historical only when aligning new code with the API.

### Quotation status workflow (session API)

Typical progression enforced by `PATCH /quotations/{id}/status`:

```
DRAFT → PENDING_APPROVAL → SENT → APPROVED → CONFIRMED or CANCELED
```

There is no `viewed` step. **Confirmed** is also set automatically when converting to an invoice, creating a job order only, or using confirm-and-convert (see quotation endpoints above).

### Invoice Total Calculation
```python
subtotal = Σ(item.quantity × item.price)
tax_amount = Σ(item.quantity × item.price × item.tax_rate / 100)

if discount_type == "percentage":
    discount_amount = subtotal × (discount_value / 100)
else:  # fixed
    discount_amount = discount_value

total = subtotal + tax_amount - discount_amount
balance = total - paid_amount
```

### Payment Recording Flow
```
1. User records payment for invoice
2. Validate: payment_amount ≤ (invoice.total - invoice.paid_amount)
3. Create payment record
4. Update invoice.paid_amount += payment_amount
5. If invoice.paid_amount ≥ invoice.total:
   → invoice.status = "paid"
```

### Payment Reversal Flow
```
1. User deletes payment
2. Get payment amount
3. Update invoice.paid_amount -= payment_amount
4. If invoice.status was "paid":
   → invoice.status = "approved"
5. Delete payment record
```

### Quotation to Invoice Conversion
```
1. Get quotation
2. Generate new invoice number
3. Create new invoice via build_invoice_doc_from_quotation():
   - Copy client_id, terms, discount, currency
   - Copy all line items (set tax_rate = 0)
   - Set source_quotation_id
   - Set status = "draft"
4. Update quotation:
   - Set converted_invoice_id
   - Set status = "confirmed"
5. Return new invoice
```

### Confirm-and-Convert Flow
```
1. Load quotation by ID
2. In one request:
   - Generate invoice number and insert invoice (same field mapping as convert-to-invoice)
   - Generate job order number and insert job order from quotation line items
   - Set quotation status = "confirmed", converted_invoice_id, and converted_job_order_id
3. Return { invoice, job_order }
```

### Quotation to Job Order Conversion
```
1. Get quotation
2. Generate new job order number
3. Create job order via build_job_order_doc_from_quotation():
   - Copy client_id, currency, items
   - Set source_quotation_id
   - Set status = "active"
4. Return new job order
```

### AI PDF Extraction Flow
```
1. User uploads PDF
2. Get DeepSeek API key from company_settings
3. Extract text from PDF using extract_text_from_pdf() (PyPDF2)
4. Call DeepSeek API (OpenAI-compatible) with structured extraction prompt
5. Parse JSON response:
   {
     company_name,
     company_address,
     proposal_number,
     phases: [],
     items: [{name, description, quantity, price}]
   }
6. Return extracted data to frontend
7. Frontend pre-fills job order form
8. User reviews and saves
```

### Recurring Invoice Processing Flow
```
1. POST /recurring-invoices/process is called (manual trigger or scheduler)
2. Query all active recurring schedules where next_date ≤ today (and end_date not passed)
3. For each due schedule:
   a. Load source invoice by invoice_id
   b. Generate a new invoice number
   c. Insert new invoice (draft) with recurring_source_id pointing at the schedule
   d. Advance next_date by interval (weekly/monthly/quarterly/yearly)
4. Return { generated: count }
```

### Revenue Dashboard Calculation
```
1. Get all invoices with status="paid" for selected year
2. Group by month → monthly_revenue
3. For each paid invoice:
   - Split total equally among consultant_ids
   - Aggregate per consultant → consultant_revenue
4. Return {year, total_revenue, monthly_breakdown, consultant_breakdown}
```

### Email Sending Flow
```
1. Caller provides document ID, recipient email, subject, body, email_account_id
2. _resolve_email_account() selects the configured SMTP or Gmail account
3. Apply template placeholders (apply_email_template_placeholders)
4. Append HTML signature (_append_signature_html)
5. Generate PDF for the document (invoice/quotation/job order)
6. send_email_with_attachment() dispatches via:
   - SMTP: _send_smtp_email() in threadpool executor
   - Gmail API: _send_gmail_api_sync() using service account in threadpool executor
```

## 🚀 Getting Started

### Prerequisites
- Node.js 18+
- Python 3.11+
- MongoDB 7.0

### Backend Setup
```bash
cd backend
pip install -r requirements.txt
# Alternative from the repository root: pip install -r requirements.txt
# Copy and configure .env file
cp .env.example .env
# Create uploads directory
sudo mkdir -p /app/uploads && sudo chmod 777 /app/uploads
uvicorn server:app --host 0.0.0.0 --port 8001 --reload
```

### Frontend Setup
```bash
cd frontend
yarn install
# Copy and configure .env file
cp .env.example .env
yarn start
```

Use **yarn** only for the frontend (`package-lock.json` is not used). The dev server proxies `/api` to `REACT_APP_BACKEND_URL` (default `http://127.0.0.1:8001`).

**Docker:** The image runs **one** process (`uvicorn` on **port 3000**) serving the API and the built SPA. Local development uses **two** processes (API **8001**, CRA **3000**).

**Automated tests:** With MongoDB and the API running, from the repo root run `python3 -m pytest backend/tests -q`. Frontend: `cd frontend && yarn test --passWithNoTests`. Optional manual checks: `backend_test.py`.

### Using Supervisor
```bash
sudo supervisorctl start all
sudo supervisorctl status
sudo supervisorctl restart backend
sudo supervisorctl restart frontend
```
